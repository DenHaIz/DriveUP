# DriveUP — handoff

Состояние на 24.10.2026, версия **1.3.0** (выпущены v1.0.0, v1.1.0, v1.2.0). Репозиторий: https://github.com/DenHaIz/DriveUP.

Две редакции из одних исходников: **DriveUP** (драйверы) и **DriveUP Pro** (то же + вкладка «Оптимизация»,
бордово-красное оформление). Pro описана в разделе «DriveUP Pro» ниже.

## Что это

Обновление и установка драйверов Windows в одном `.exe` на каркасе Wisp Cleaner (`..\Wisp Cleaner`), который
сам вырос из Lighter: тот же стек (C# 5, WinForms со своей отрисовкой, встроенный `csc.exe`), палитры, движок
анимаций, переходы, контролы, масштаб от размера окна, RU/EN. Четыре вкладки:

- **Обновления** — большое кольцо (логотип) + «Проверить обновления» / «Установить (N)»; справа обновления из
  Windows Update по группам устройств с галочками; карточка «Точка восстановления» и «Проверять при запуске».
- **Устройства** — все подключённые устройства: версия/дата/поставщик драйвера, состояние (работает / ошибка /
  есть обновление). Фильтры, поиск, «Свойства» (окно Диспетчера устройств), «Найти драйвер» (каталог Microsoft
  по ИД оборудования), «Обновить конфигурацию», контекстное меню.
- **Установка** — зона сброса: папка, `.inf`, `.zip`, `.cab` (или кнопки выбора). Список найденных драйверов:
  для каких устройств подходят, отметить → «Установить отмеченные». `.exe`/`.msi` — предложение запустить.
- **Резервные копии** — сторонние пакеты из хранилища драйверов (`oemNN.inf`): сохранить копию, восстановить
  (папка открывается на «Установке»), удалить неиспользуемые старые версии (сначала копия, потом удаление).

Проверка при запуске включена, точка восстановления включена. Фоновых задач, трея и автозапуска нет.

## Сборка и релиз

- `build.cmd` → `bin\DriveUP.exe` и `bin\DriveUP_Pro.exe` (оба требуют администратора). `build.cmd dev` → ещё
  `DriveUP.dev.exe` / `DriveUP_Pro.dev.exe` с `asInvoker` — без UAC, отдельные экземпляры (`Program.Instance` =
  `Edition.Id` + `.Dev`).
- Pro = `src\*.cs` + `src\Pro\*.cs` с `/define:PRO`. Всё отличие обычной версии — в `#if PRO` (`Edition.cs`,
  `AssemblyInfo.cs`, `Theme.cs`, `Settings.cs`, `MainForm.cs`); в `DriveUP.exe` кода настройки нет вовсе.
- Иконки: `tools\MakeIcon.cs` рисует `obj\app.ico` и (с `/define:PRO`) `obj\app_pro.ico` кодом из `src\Logo.cs`;
  `obj\MakeIcon.exe app.ico --png <папка>` — PNG. `docs\logo.png`, `docs\logo_pro.png` — для README.
- Релиз: `.github\workflows\release.yml` собирает по тегу `vX.Y.Z` и публикует оба exe + `.sha256`.
- Репозиторий: `github.com/DenHaIz/DriveUP`, ветка `main`, релиз `v1.0.0` (только обычная версия).

## Логотип

Открытое кольцо Lighter (247° от 12 часов, круглые концы), внутри — стрелка вверх над чертой («обновить»)
той же толщиной линии, что метла Wisp. Фиолетовый `#9D6BFF` на плитке `#33353B → #27282C`. Меньше 40 px линии толще.

Выбор шёл в два раунда, листы в корне (в репозиторий не обязательны): `logo-variants.png` (стрелка, стрелка в
просвет, чип, кольцо-обновление, шевроны, лоток) и `logo-arrows.png` (уточнения стрелки). Сначала был выбран
№ 2 «Стрелка и штрихи Lighter», затем по просьбе заменён на **№ 3 «Стрелка над чертой»**. Листы рисовал
отдельный C#-скрипт (GDI+), не HTML.

Штрихи и стрелки рисуются одной заливкой (`Logo.FillStroke`: контур расширяется `Widen` и заливается один раз),
поэтому у полупрозрачной стрелки нет тёмного стыка древка и наконечника.

## DriveUP Pro

**Оформление.** Тот же знак, цвет `Logo.Mark` = `Logo.Crimson` `#D6304F` (обычная — `Logo.Violet`). В Pro весь
акцент красный: `Theme` (статический конструктор под `#if PRO`) — Accent `#D6304F`/`#C0263F`, Selected, а Danger
сдвинут в красно-оранжевый `#FF8A5B`/`#D9541E`, чтобы ошибки не путались с акцентом. В шапке «DriveUP **Pro**»
(Pro цветом знака). Файлы: `DriveUP_Pro.ini`, `DriveUP_Pro.log`; папка резервных копий общая с обычной версией.

**Вкладка «Оптимизация»** (`src\Pro`): слева «Умный подбор» (что за компьютер + рекомендация) и три карточки
режимов; справа переключатель «Что изменится» / «Изменено · N».

- «Что изменится»: строки «сейчас → станет» с причиной; «уже так» — без галочки; «вернётся» — что менял другой
  режим, а этому не нужно; «после перезагрузки» — жёлтая метка. «Применить» идёт по строкам (крутилка → галочка
  или «!» с причиной), затем сам открывается вид «Изменено»; если нужна перезагрузка — спрашивает.
- «Изменено»: всё, что DriveUP Pro поменял и ещё не вернул: «было → сейчас», каким режимом и когда, у каждой
  строки своя кнопка «Вернуть» (строка сворачивается), внизу «Вернуть всё». Записи в журнал: `Tune`, `TuneReturn`.

**Как устроено.** `Tweak` (Tweaks.cs): `Capture()` — точное старое состояние (вплоть до «значения не было»),
`Restore(raw)`, `ValueOf(raw)`, `Set(value)`, `Describe`, `Available(Machine)`, `Extend(saved)`. `Tuner.Change`
сначала сохраняет старое состояние, потом меняет; не сохранилось (`Settings.Save()` вернул false) — ничего не
меняет. Хранилище — **`HKLM\SOFTWARE\DriveUP Pro`** (`Saved.<id>`, `When.<id>` = «режим|время», `TuneMode`):
пишут только администраторы, переживает удаление/перенос exe, строки хранятся точно. Записи 1.1/1.2 из
`DriveUP_Pro.ini` читаются (`LoadIni`) и при первом сохранении переезжают в реестр. Повторная смена хранит самое
первое состояние; `PowerSetting.Extend` дописывает старые значения каждой следующей схемы («схема|ac|dc;…»), так что
«Игры» → «Тишина» → «Вернуть всё» возвращает все схемы. Если после смены значение совпало с исходным — запись
снимается («Изменено» её больше не показывает). При ошибке `Set` старое восстанавливается, и запись снимается
только если восстановление удалось. Порядок: возвраты с конца каталога, изменения с начала (схема питания раньше
своих параметров); если режим меняет схему, все её параметры пишутся заново (строки «уже так» → «изменится»).

**Настройки** — 30+ пунктов в 9 группах (`TuneCat`: питание, игры, интерфейс, службы, задачи, автозагрузка,
реклама, система, обновления); в списке группы с заголовком-галочкой «выбрано N из M». Только известные и
обратимые; «твики» вроде Nagle, NetworkThrottlingIndex, SystemResponsiveness, Win32PrioritySeparation и
отключения служб Xbox/обновлений/защиты сознательно не взяты.

**Ноутбуки, Modern Standby, рабочие ПК (с 1.1.1).** Жалоба на 1.1.0: после «Тишины» ноутбук висел ~30 мин на
«Перезагрузка…», а от батареи при запуске была ошибка батареи. Причина точно не установлена (здесь нет ноутбука),
вероятные: классическая схема «Экономия энергии» на ноутбуке, принудительное «максимальное» энергосбережение
PCIe (ASPM) от сети (известные зависания NVMe/Wi-Fi), USB selective suspend и изменение стороны «от батареи»
(буст, EPP). Теперь:
- `Machine.Mobile` = ноутбук или Modern Standby (`GetPwrCapabilities`, байт 20 AoAc). Для них схема питания —
  только «Сбалансированная» + режим питания (overlay), классические схемы не включаются никогда (на AoAc — даже
  без overlay); все `PowerSetting` — только сторона «от сети» (`x,*`), батарея остаётся Windows и производителю.
- «Тишина» больше не трогает PCIe ASPM и USB suspend ни на каких ПК (Windows и так экономит от батареи).
- «Игры» от батареи: схема питания — только по желанию; HAGS на ноутбуках (две видеокарты) — только по желанию.
- `Machine.Managed` (домен `PartOfDomain`, Entra ID `CloudDomainJoin\JoinInfo`, MDM `Enrollments` с UPN): не
  предлагаются DiagTrack, dmwappushservice (через неё приходят команды Intune), задачи телеметрии, TrkWks,
  целостность памяти. `Machine.SecureBiometrics` (Windows Hello ESS) — целостность памяти не предлагается.
- Перед «Применить» — точка восстановления (если включена настройка «Точка восстановления перед установкой»).
- Аварийный возврат: `DriveUP_Pro.exe /restore` — возвращает всё изменённое без окна, итог в окне сообщения и в журнале.

**1.2: рискованное — только с разрешения, фоновые процессы, новые пункты.**
- Риск = у шага есть `Warn` (что сломается или ослабнет). `StepsFor` делает такие шаги необязательными
  (`Optional`), они никогда не отмечены сами; если пользователь их отметил, «Применить» сначала показывает окно со
  списком «пункт — чем грозит» и без «Применить» в нём ничего не делает. Сейчас рискованные: целостность памяти,
  HAGS (на всех ПК), индексирование поиска, запись Game Bar, гибернация, облачные диски, «Связь с телефоном»,
  Почта и Календарь, To Do, Xbox, обновление Acrobat, Диспетчер печати, фоновые приложения Store (Win10),
  схема «Игр» от батареи. Тест проверяет, что ни один рискованный пункт не отмечен ни в одном режиме.
- Новая группа «Фоновые процессы» (`TuneCat.Background`): виджеты Win11 (политика `Dsh\AllowNewsAndInterests`) /
  «Новости и интересы» Win10, предзапуск и фоновый режим Edge (политики `StartupBoostEnabled`,
  `BackgroundModeEnabled`), разрешение фоновой работы установленных приложений Store
  (`BackgroundAccessApplications\<PFN>` Disabled/DisabledByUser; предлагаются только установленные — ключ в
  `AppModel\Repository\Families`). Уровни как у автозагрузки: 1 мусор, 2 тяжёлое, 3 на ваш выбор.
- Автозагрузка теперь видит и приложения Store (`AppModel\SystemAppData\<PFN>\<Task>\State`: 2 вкл, 1 выкл
  пользователем — как Диспетчер задач), id `pkg.<base64>`; пауза автозагрузки (`Serialize\StartupDelayInMSec=0`, на SSD).
- Ещё службы: сетевой доступ WMP, телеметрия Intel (QUEENCREEK ×2) и HP; по выбору — Диспетчер печати (не на
  рабочих ПК) и обновление Acrobat.
- Ещё пункты: VRR-оптимизация (`VRROptimizeEnable`), задержка меню 100 мс (`SPI_SETMENUSHOWDELAY`), отключение
  EcoQoS (`PowerThrottlingOff`, «Игры» на ПК), гибернация (`powercfg /hibernate`, показывает размер hiberfil.sys),
  журнал действий, персональные советы, отчёты об ошибках (не на рабочих ПК).
- В строках — сколько процессов этой программы висит сейчас и сколько памяти они держат (`Tweak.Processes`,
  `Running.Snapshot`), внизу — итог «уйдёт из фона».
- Не сделано: Delivery Optimization (настройка живёт в `HKU\S-1-5-20`, без прав администратора её даже не
  прочитать — не проверить), удаление приложений (только отключение, всё возвращается).

**1.2: проверка кода (два независимых обзора) и исправления.**
- Pro: см. «Как устроено» выше (хранилище в HKLM, Extend по схемам, отказ без сохранения); режим питания (overlay)
  хранится вместе с источником питания («схема|режим|ac/dc»): на ноутбуке от батареи он не меняется вовсе (строки
  нет, `Set` отказывает), возврат на «чужом» источнике отказывает с просьбой подключить/отключить зарядку и
  оставляет запись; ноутбук/Modern Standby без overlay классическую схему не получает никогда. «Оптимизация оконных
  игр» и VRR сохраняют и возвращают только свою пару в строке DirectX. Рискованное (`Warn`) не отмечается ни в
  каком источнике (режимы, «Фоновые процессы», автозагрузка). Страница помнит, для какого режима построены строки
  (`rowsMode`), и «Применить» неактивна, пока план читается. Неудавшиеся строки можно применить/вернуть снова.
  Вопрос о перезагрузке задаётся всегда. `/restore` не работает при открытом окне (общий мьютекс). Подсказка над
  строкой — полные тексты (причина, последствия, ошибка); в «Изменено» заголовок группы возвращает всю группу.
- Основная часть: «старые версии» — только действительно старее (равная версия или неизвестная не удаляется);
  `InfsInUse` — недочитанный список устройств = ошибка; закрытие окна во время Windows Update предлагает прервать
  (`WinUpdate.RequestAbort` → `IUpdateJob.RequestAbort`, окно закрывается, когда остановится); ожидание сайтов
  производителей 46 с (их собственный предел 40 с — частичные результаты больше не теряются); после установки
  через Windows Update устройства перечитываются, находки сайтов для уже обновлённых устройств исчезают, вкладка
  «Резервные копии» перечитывается при следующем открытии; ссылка NVIDIA — только на `www.nvidia.com`; если
  сброшено несколько установщиков — называются остальные.
- Не сделано из обзора: отмена установки по кнопке (только через закрытие окна), принудительная установка более
  старой версии из копии (`DIIRFLAG_FORCE_INF`).
- Не проверено (нужны права администратора): защищённая папка в `%SystemRoot%\Temp`, запись в
  `HKLM\SOFTWARE\DriveUP Pro`, прерывание Windows Update, OneDrive.

Не проверено (нужен администратор/железо): установка компонентов, удаление приложений, пауза обновлений, HP и Dell на
настоящих ПК (сопоставление проверено на их реальных файлах), время загрузки из журнала.

Смена режима: всё, что менял прежний режим, а новому не нужно, попадает строкой «вернётся» (например,
«Работа» возвращает минимальную частоту и парковку ядер, выставленные «Играми»).

**Умный подбор** (`Tuner.Recommend`): от батареи → «Тишина»; игровая видеокарта (NVIDIA; AMD RX/Pro/Vega; Intel
Arc A/B, но не встроенная «Arc Graphics») → «Игры»; иначе «Работа». `Machine.Read`: корпус (`Win32_SystemEnclosure`,
батарея без «ноутбучного» корпуса может быть ИБП), процессор и ядра, память, системный диск (`MSFT_Partition` →
`MSFT_PhysicalDisk`: NVMe по шине 17, SSD/HDD по MediaType), есть ли HDD, видеокарты, HAGS, сборка Windows из
реестра (`Environment.OSVersion` без манифеста врёт: 9200), Server.

**Проверено** (`scratchpad\pro\ProTest.cs`; с `Reg.TestRoot` реестр, схемы питания, службы, задачи, мышь и
анимации уходят в `HKCU\Software\DriveUP.ProTest`, настоящие только читаются): службы (тип запуска и отложенный
старт обратно), задачи (каждая в своё состояние), автозагрузка (только из списка, системные — никогда; флаг снимается
при возврате), анимации, реклама, питание (схема → значения ложатся в новую схему → возврат обеих), а также: смена/возврат каждого
значения вплоть до удаления, сохранение чужих пар в строке DirectX, откат при ошибке, первое состояние при
повторной смене, планы с/без HAGS и на Win10, «вернётся» при смене режима, порядок, `.ini` после перезапуска,
снимки страницы (тёмная RU / светлая EN: план, применение, «Изменено», возврат одной и всех). **Не проверено**
(нужны права администратора и железо): реальная запись HKLM, смена схемы/overlay и буста, `SPI_SETMOUSE`, HAGS и
целостность памяти после перезагрузки, ноутбук от батареи. Учесть: HKCU — профиль того, под кем запущено
повышение (обычно тот же пользователь; при вводе чужого админского пароля — профиль админа).

## Большое кольцо (`UpdateRing`) — без разрывов

Кольцо — всегда одна дуга (начало, длина, цвет). Состояние задаёт только цель; при смене состояния дуга едет
к ней из того места, где нарисована сейчас (с запасом целых оборотов, чтобы не крутиться назад). Поэтому:
крутящийся индикатор поиска замедляется и встаёт в логотип, просвет логотипа закрывается в полное кольцо,
полное кольцо раскручивается обратно в индикатор.

- Покой: стрелка над чертой. Поиск: индикатор «голова убегает — хвост догоняет», стрелки выходят из черты и
  гаснут до верха (снизу обрезаются чертой, сверху — гаснут, не обрезаются).
- Готово: число обновлений. Установка: дуга заполняется, по ней бежит блик (видно, что работа идёт, даже когда
  процент стоит), в центре процент. Всё актуально / установлено: кольцо закрывается, рисуется галочка.
  Ошибка: янтарное кольцо и знак «!» той же толщиной линии.
- Центр и подпись сменяются по очереди (старое уходит вверх и гаснет, новое приходит снизу) — никогда не
  накладываются. У уходящей галочки/знака своя «фаза появления», они не перерисовываются заново.
- Проверка: тестовый стенд снимает ленту кадров через все переходы (см. «Что проверено»).

Другие анимации, сделанные непрерывными: подписи кнопок (`FlatButton`) и строки статуса (`StatusText`)
сменяются плавно; ширина главной кнопки меняется плавно; зона сброса на «Установке» перетекает из крупного вида
в полосу без скачка раскладки на середине (все позиции интерполируются), бегущий пунктир не дёргается назад.

## Источники данных (без разбора локализованного текста)

- **Обновления** — `Microsoft.Update.Session`, критерий `IsInstalled=0 and Type='Driver' and IsHidden=0`,
  `ServerSelection = ssWindowsUpdate` (WSUS обычно без драйверов; при запрете политикой — по умолчанию).
  Поиск занимает от секунд до пары минут — на кольце и в подсказке идут этапы. Скачивание и установка —
  `BeginDownload`/`BeginInstall` с пустыми COM-колбэками (`WuCallbacks`, интерфейсы `public` — иначе COM их не
  видит), прогресс опрашивается у задания каждые 150 мс: скачивание 0–45 %, установка 45–100 %.
- **Устройства** — `SetupDiGetClassDevs(DIGCF_PRESENT | DIGCF_ALLCLASSES)`; узлы без имени (`HTREE\ROOT\0`) скрыты.
  Обновление привязывается к устройству по `DriverHardwareID` среди ИД оборудования/совместимых ИД.
- **Хранилище** — `DriverInfFiles\oemNN.inf` → активный пакет → `DriverPackages\<пакет>`: `Provider`, `InfName`,
  `Version` (8 байт флагов, GUID класса, FILETIME даты, версия 4×16 бит). «Используется» — `DriverInfPath` любого
  устройства, в т. ч. отключённого. «Старая версия» — есть более новый пакет с тем же `InfName` и поставщиком,
  а этот никем не используется. `pnputil` не используется: его вывод локализован (и в OEM-кодировке).
- **Установка из файла** — `DiInstallDriverW`: 0 — установлен, 259 — только добавлен в хранилище (подходящих
  устройств нет или стоит не хуже), иначе — понятный текст по коду (`InfFiles.ErrorText`).
  INF: `[Version]`, `[Strings]` (с `%подстановками%`), `[Manufacturer]` → модели с декорациями `NTamd64`/`NTx86`/`NTarm64`;
  INF только для другой архитектуры отмечается и не ставится. `.zip` — `ZipFile` (защита от zip slip в .NET 4.6.1+),
  `.cab` — `expand.exe -F:*`; распакованное — в `%SystemRoot%\Temp\DriveUP-<случайно>` с правами только для
  Администраторов и SYSTEM (`SafePath.NewStaging`; без повышения прав — dev/тесты — в `%TEMP%\DriveUP`), удаляется
  при закрытии. Перед установкой драйвер из обычной папки копируется в такую же папку (`InfFiles.Prepare`, до 4 ГБ /
  20 000 файлов, иначе на месте), и SHA-256 `.inf` сверяется с прочитанным при добавлении: подменить пакет между
  «добавлено» и «установлено» нельзя (остальные файлы закрывает подпись каталога). Перед установкой — окно
  «Установить N драйверов от <поставщик>? Папка: …».

## Проверка на сайтах производителей

Идёт вместе с поиском в Windows Update (параллельно, общий лимит 40 с, каждый производитель отдельно — сбой
одного не мешает остальным). Находки — отдельные группы «На сайте …» под устанавливаемыми обновлениями: строки
без галочки, со значком «открыть»; щелчок открывает страницу загрузки (с правами пользователя). Сама установка —
скачать и перетащить на «Установку». Кольцо считает только то, что ставится из Windows Update; если там пусто,
а на сайтах есть новее — «в Windows Update новее нет» и подсказка. На «Устройствах» такие строки с акцентной
точкой «На сайте NVIDIA: 617.42», кнопка и пункт меню «Сайт производителя» есть для любого устройства.

| Производитель | Источник | Сравнение |
|---|---|---|
| NVIDIA (видео `VEN_10DE`) | `gfwsl.geforce.com/.../AjaxDriverService.php?func=DriverManualLookup&deviceID=DEV&osID=135/57` (JSON) | 32.0.15.6094 → 560.94 (последние 5 цифр двух последних частей) |
| AMD (видео `VEN_1002`) | `drivers.amd.com/drivers/installer/json/version.json` + файлы выпусков (нужен `Referer: https://www.amd.com/`; хост `www2.ati.com` заменяется на `drivers.amd.com`), совпадение по `DEV-REV` в `skus` | по `HKLM\SOFTWARE\AMD\CN\DriverVersion`, если есть; иначе дата драйвера против даты сборки из номера выпуска (`-260811a-`) |
| Intel (`VEN_8086`, `VID_8087`) | каталог Intel DSA `dsadata.intel.com/data/en` (zip → `software-configurations.json`), только пакеты для 64-бит Windows 10/11, без «Historical» и бет | по маске `VersionComparisonMask` (`X` — не сравнивать, `O` — сравнивать); без маски графика по двум последним частям; у нескольких линеек драйвера — та же линейка, если она есть в каталоге |
| Lenovo (ПК) | `download.lenovo.com/catalog/{тип машины}_Win11.xml` (или `_Win10`), затем XML каждого пакета (6 параллельно); только пакеты с `DetectInstall/_Driver` | версия из `_Driver/Version` (`^` = «эта или новее»); страница — readme пакета |
| Asus (ПК и платы) | `asus.com/support/api/product.asmx/GetPDDrivers?model={Win32_BaseBoard.Product}&osid=52/45` | только записи с `HardwareInfoList` (у ноутбуков); у плат списки без ИД — только ссылка на страницу модели |
| HP (ПК, с 1.3) | `hpia.hpcloud.hp.com/ref/{плата}/{плата}_64_{11.0}.{24h2}.cab` (всё строчными; плата = `Win32_BaseBoard.Product`, напр. `880d`); нет файла для выпуска — ближайший из `ref/platformList.cab` | `Device/DeviceId` (как у Lenovo, по ИД с продолжением) и `DriverVersion`; страница — `ReleaseNotesUrl` SoftPaq |
| Dell (ПК, с 1.3) | `downloads.dell.com/catalog/CatalogIndexPC.cab` (UTF-16) → каталог модели по `Model systemID` = `SystemSKUNumber` | только пакеты `DRVR` и только по `PCIInfo` (VEN/DEV/SUBSYS) и `PnPInfo` (USB VID/PID), версия — `Device version`; по названиям не сопоставляется |
| Каталог Microsoft Update (любой чип, с 1.3) | `catalog.update.microsoft.com/Search.aspx?q={ИД}` (сначала самый точный ИД без REV, потом VEN&DEV), `ScopedViewInline.aspx?updateid=` | строка подходит, только если её «Products» — эта Windows (11/10) и выпуск «version XXHX and later» не новее текущего, версия новее, а в списке ИД драйвера есть **точный** ИД устройства (много записей сделано под платы одного производителя ПК). Проверяются устройства Realtek, MediaTek, Qualcomm, Broadcom, AMD (не видео), Intel (не видео), ASMedia, Renesas, Synaptics, ELAN и др., плюс любые с ошибкой; до 24 устройств, 4 потока, 33 с |

Если на одно устройство есть и пакет производителя ПК, и драйвер производителя чипа, показывается пакет ПК
(он сделан для этой модели); каталог Microsoft — последним. Находки каталога не ссылки, а «скачать»: `.cab` берётся
с `*.windowsupdate.com` по HTTPS (`DownloadDialog.aspx`), кладётся в защищённую папку и открывается на «Установке»
(там распаковка, сопоставление и обычное подтверждение). «Найти драйвер» на «Устройствах» ищет в каталоге прямо в
программе (для устройства без драйвера — любую версию) и предлагает скачать; не нашлось — открывает поиск в браузере.
Исследованы и не подключены (нет машиночитаемых списков или адрес сервера разработки заблокирован): Samsung,
Surface, Xiaomi (только названия), Huawei, Razer, MSI, Gigabyte, ASRock, Acer, Biostar, страницы Realtek и AMD.
Intel: в каталоге DSA есть Killer-сеть на чипах Realtek — теперь проверяются и устройства `VEN_10EC`. Страница «Сайт производителя»: найденная проверкой; для видеокарт — производитель
чипа; иначе страница производителя ПК для этой модели (Lenovo по типу машины, Asus по модели, Dell, HP, Surface);
иначе производитель чипа по коду `VEN_`/`VID_` (Realtek, Qualcomm, Broadcom, MediaTek, Marvell, Synaptics, ELAN…).

Важно: exe собирается встроенным `csc` без отметки целевой платформы, поэтому .NET по умолчанию предложил бы
только старый TLS — `VendorCheck` включает TLS 1.2 (и 1.3, где есть). JSON — `JavaScriptSerializer`
(`System.Web.Extensions.dll` в `build.cmd`).

## Безопасность (приложение работает от администратора)

По итогам отдельной проверки кода:
- Системные программы (`shutdown.exe`, `rundll32.exe`, `expand.exe`) — только по полному пути; диалоги выбора
  файла/папки не меняют текущую папку (`RestoreDirectory`, `FOS_NOCHANGEDIR`). ИД устройства с кавычкой не
  передаётся в командную строку.
- DLL: `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` в начале `Main` и
  `[assembly: DefaultDllImportSearchPaths(System32)]` — подложенная рядом с exe DLL не загрузится.
- Установщики `.exe`/`.msi` (из сброса, выбора или командной строки) запускаются через Проводник с правами
  пользователя: Windows сама спросит права администратора и покажет настоящего издателя. В вопросе — полный путь.
- Ссылки определяются по тегу точки повторной обработки (`SafePath.IsLink`: только junction/symlink —
  «name surrogate»); папки и файлы OneDrive (облачные теги) ссылками не считаются, поэтому копии в «Документах»
  с резервным копированием OneDrive работают (не проверено на настоящем OneDrive).
- Резервная копия: в корне копий ссылки (junction) запрещены; новая папка получает собственные права
  (Администраторы, SYSTEM, текущий пользователь, без наследования), проверяется на подмену ссылкой; файлы не
  перезаписываются.
- Удаление старых версий: только когда новейшая версия того же драйвера уже используется; расширения,
  программные компоненты, принтеры не трогаются; перед удалением Windows заново спрашивается, кто что использует
  (сбой перечисления = ошибка, а не «никто»); удаляется только то, что успешно скопировано.
- `.cab` распаковывает `expand.exe`, `.zip` — `ZipFile` (zip slip запрещён .NET 4.6.1+); обоим — защищённая папка.
- Точка восстановления не создалась (а восстановление системы в Windows есть) — установка спрашивает
  «Продолжить без точки?» (`SysRestore.ContinueWithout`); на Server без восстановления — не спрашивает.
- Запросы к сайтам производителей: только GET на зашитые адреса, ответы до 16 МБ, тайм-ауты, XML без DTD.

## Плавность

- Журнал кадров: `set DRIVEUP_FRAMELOG=C:\путь\frames.log` (как `WISP_FRAMELOG` в Wisp).
- Замер (RDP, окно 1180×720, старт + проверка + переключения вкладок): работа кадра p95 5,9 мс, опоздание кадра

  `DiInstallDriver` с успехом, удаление старых версий, точка восстановления (на Windows Server её нет);
- проверка на сайтах на настоящем железе NVIDIA/AMD/Intel/Lenovo/Asus (проверено на подставных устройствах):
  у AMD — значение `HKLM\SOFTWARE\AMD\CN\DriverVersion` (если его нет, сравнение по дате); у Asus версия пакета
  обычно совпадает с версией INF, но не всегда — возможны лишние отметки;
- перетаскивание из Проводника в повышенное окно — в этой сессии нет интерактивного рабочего стола;
- контекстное меню «Устройств», диалоги выбора, запрос перезагрузки — кликом не проверялись.

## Подводные камни

- C# 5: нет `$""`, `?.`, `nameof`. Глифы Segoe MDL2 писать только как `\uXXXX` (сейчас все так).
- Всё, что рисуется только в `WM_PAINT`, должно рисоваться и в `WM_PRINTCLIENT` (снимки для переходов).
- Размеры — в дизайн-пикселях через `S()` при каждой раскладке (см. Wisp HANDOFF).
- Потоки Windows Update — MTA (`WinUpdate` через `dynamic`, нужна ссылка на `Microsoft.CSharp.dll`); потоки с
  SetupAPI-диалогами (`DiInstallDriver`) — STA.
- Подписчики `Inventory.Changed` проверяют `IsDisposed`: событие статическое.
- Проверки без мыши: `DriveUP.dev.exe /tab:N` переключает вкладку уже запущенной копии; скриншоты в этой среде —
  через `PrintWindow` (`CopyFromScreen` недоступен без интерактивного рабочего стола).

## Как проверять от администратора

1. `build.cmd`, запустить `bin\DriveUP.exe` (UAC).
2. «Обновления» на ПК, где Windows Update предлагает драйверы (Параметры → Центр обновления → Дополнительные
   обновления) → «Установить» → кольцо идёт 0→100 %, строки уходят из списка, запись в «Журнале».
3. «Установка»: перетащить из Проводника папку драйвера (например, скачанный с catalog.update.microsoft.com `.cab`) →
   строка «Готов к установке» → «Установить отмеченные» → «Установлен» / «Добавлен в хранилище».
4. «Резервные копии» → «Сохранить копию» → папка в «Документы\DriveUP Backup\дата»; «Восстановить из копии…» →
   эта папка открывается на «Установке». На ПК со старыми версиями — «Удалить старые версии»: сначала копия в
   «…\Удалённые старые версии\дата», потом удаление; используемые Windows не даст удалить.
